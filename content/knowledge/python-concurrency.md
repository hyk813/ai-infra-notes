## 一分钟回答

在传统带 GIL 的 CPython 中，同一进程通常不能同时执行多个线程的 Python 字节码。不过 I/O 等待和释放 GIL 的原生代码可以改变并行情况。

## 如何选择

| 工作负载 | 常用方式 | 主要成本 |
| --- | --- | --- |
| CPU 密集型 Python 计算 | 多进程或原生扩展 | 序列化、通信、数据复制 |
| 阻塞 I/O | 线程池 | 线程数量与调度 |
| 大量可异步执行的 I/O | 协程 | 事件循环被阻塞的风险 |
| GPU 执行 | 合理组织主线程与执行流 | 提交、同步与数据准备 |

## 原生扩展

长时间执行的 C++ 函数可以考虑释放 GIL，前提是不访问需要 GIL 的 Python 对象，并正确管理线程安全与资源生命周期。

## 容易混淆

- 协程不会自动加速 CPU 计算。
- Python 线程可能并行执行释放 GIL 的原生计算。
- 多进程并不一定更快，搬运大型张量可能成为新的瓶颈。
