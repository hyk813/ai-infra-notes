## 核心结论

先准备目标副本，再发布位置；旧副本必须等读取者与相关操作完成后释放。

## 一个提升流程

以 DRAM 到 HBM 为例：

1. 选中 Block，标记迁移状态。
2. 保留 CPU 副本，分配目标 GPU 空间。
3. 提交 H2D；继续运行其他不依赖该 Block 的工作。
4. 使用完成事件确认数据可用。
5. 发布新位置，等旧副本没有使用者后释放。

## 新请求命中迁移中的 Block

| 状态 | 可以采用的处理 |
| --- | --- |
| 提升尚未完成 | 复用同一个迁移任务，避免重复读取 |
| 淘汰尚未开始 | 重新评估评分并取消过期任务 |
| 旧副本仍有效 | 固定该副本并延迟回收 |
| 旧副本已释放 | 从当前有效位置重新获取 |

## 容易忽略的地方

CPU 函数返回，不代表 GPU Kernel 已完成。进程池也不等于 GPU 拷贝自动重叠，需要正确组织缓冲区、CUDA Stream 和 Event。

如果 SSD 已有完整有效副本，CPU 淘汰不一定需要写回。
